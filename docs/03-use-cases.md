# Use Cases

## UC-01: Бронирование поездки пассажиром

**Актор:** Пассажир
**Предусловие:** Пассажир авторизован, водитель опубликовал поездку со свободными местами

### Основной поток

1. Пассажир открывает карточку поездки
2. Система отображает маршрут, время, цену и количество свободных мест
3. Пассажир нажимает «Забронировать»
4. Система создаёт заявку в статусе «Ожидает подтверждения» и уведомляет водителя

### Альтернативный поток A1: Мест нет

1. Система блокирует кнопку бронирования и показывает сообщение «Свободных мест нет»

### Исключительный поток E1: Водитель отклонил заявку

1. Система меняет статус заявки на «Отклонена» и уведомляет пассажира с предложением выбрать другую поездку

### Постусловие

Бронь создана в статусе PENDING. Количество свободных мест не изменилось до подтверждения водителем.

## UC-02: Создание поездки водителем

**Актор:** Водитель
**Предусловие:** Водитель авторизован

### Основной поток

1. Водитель нажимает «Создать поездку»
2. Система запрашивает маршрут, время, количество мест, цену
3. Водитель заполняет форму и нажимает «Опубликовать»
4. Система валидирует данные и создаёт поездку в статусе ACTIVE
5. Система показывает поездку в списке доступных

### Исключительный поток E1: Некорректные данные

1. Система возвращает 422 и подсвечивает поля с ошибками

## UC-03: Отмена брони пассажиром

**Актор:** Пассажир
**Предусловие:** Бронь существует в статусе PENDING или CONFIRMED

### Основной поток

1. Пассажир нажимает «Отменить бронь»
2. Система проверяет время до отправления
3. Если ≥2 часов — бронь отменяется без штрафа, статус CANCELLED
4. Если <2 часов — система предупреждает о штрафе 50%
5. Пассажир подтверждает отмену со штрафом
6. Система меняет статус на CANCELLED и удерживает штраф
